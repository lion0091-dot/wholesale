# 개인정보 유출 대응 절차 (초안, 2026-09-30)

> 변호사 확인 전 초안이다. 통지·신고 기한과 대상 기준은 자문서 질문 6의 답으로 확정한다(개인정보 보호법 제34조 기준 추정: 유출을 안 시점부터 정보주체 통지는 지체 없이, 일정 규모 이상은 관계기관 신고).

## 1. 유출로 볼 신호
- 다른 업체 데이터가 보인다는 제보(RLS 우회 의심)
- 관리자/서비스 계정 탈취 의심(모르는 로그인, `access_log`의 낯선 IP)
- 서비스 키(`SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`, `CREDENTIAL_ENCRYPTION_KEY`) 노출
- 사업자등록증·명세서 보관함 파일이 외부에 공개된 정황

## 2. 초동 조치 (알게 된 즉시)
1. 대표에게 즉시 보고하고 시각을 기록한다(알게 된 시점 = 통지 기한의 기준).
2. 노출 경로를 막는다: 노출된 키 재발급(Vercel 환경변수, Supabase), 의심 계정 정지(`auth.admin.updateUserById` ban), 문제 화면 배포 롤백.
3. 증거를 보존한다: `access_log`(접속기록), `audit_log`(변경 이력), Vercel·Supabase 로그를 삭제하지 말고 내려받는다.

## 3. 범위 파악
- 누구의 어떤 정보가 얼마나(건수) 나갔는지: 회원(공급사·고객사), 손님 명단, 명세서 파일, 사업자등록증.
- 로그인 정보(카카오)·비밀번호형 자격정보(알림톡·PG, AES-256-GCM 암호화 저장) 포함 여부.

## 4. 통지·신고 (기한·대상은 변호사 확인)
- 정보주체(회원) 통지: 유출 항목, 시점·경위, 피해 최소화 방법, 담당 부서·연락처.
- 관계기관 신고: 개인정보 보호위원회 또는 한국인터넷진흥원(KISA) — 신고 대상 규모 기준 확인 필요.
- 공급사가 입력한 손님 명단이 유출된 경우 해당 공급사에게 먼저 알린다(공급사가 처리자일 가능성, 질문 1).

## 5. 사후
- 원인 수정과 재발 방지, 방침·약관 반영, 경위서 작성(날짜·조치·통지 내역).
- 담당자: 개인정보 보호책임자(방침 10조에 기재된 대표) / 연락처: 방침 10조 기재 이메일.
