# 입고 경우의 수 정리 (발생 → 처리 → 결과)

2026-10-03 작성. `docs/livestock-inbound-tracking.md`, `docs/purchase-order-receiving.md`, `lib/livestock/*`를 읽고 정리했다. DB 함수 본문을 한 줄씩 대조하지 않았고 실화면 클릭 검증도 없다. 문서 속 "전표"는 지금은 "발주서"를 가리키며, 명세서 대조 기능은 마이그레이션 152에서 제거됐다.

## A. 입력 단계

| 발생 | 처리 | 결과 |
|---|---|---|
| 지금 온 거래처 미선택 | 화면이 차단 | 입고 안 됨 (엑셀은 예외) |
| 이력번호나 실중량이 빈칸 | 화면 안내 | 입고 안 됨 |
| 같은 번호, 같은 중량, 10분 이내 | `DUPLICATE_SUSPECTED` 확인창 | "다른 박스 맞음"을 누르면 입고, 아니면 취소 (엑셀·분류입고는 검사 제외) |

## B. 이력 조회 실패 (`EXCEPTION`, 재고에 안 들어감)

| 발생 | 처리 | 결과 |
|---|---|---|
| 인증키 미등록 | 키가 등록되면 자동 재조회. 급하면 상품 직접 지정 | 지정 시 재고 반영 |
| API 일시 오류 | 화면이 열려 있으면 5분마다 3건씩 재조회 (같은 박스는 30분 간격). 매일 크론도 있음. 수동은 "다시 조회" | 성공하면 정상 입고로 이어짐 |
| 번호 못 찾음 (오타, 미등록, 공급처 자체 코드) | "번호 바꾸기"(옛 박스 VOIDED, 무게·기한·단가는 새 박스로 이전) / 이력 등록 시 자동 재조회 / 상품 직접 지정 / "주문에 바로 배정" | 어느 쪽이든 정해지는 순간 재고 반영 |
| 같은 번호로 재조회해도 못 찾음 | DB를 건드리지 않음 | 박스 그대로 |
| 이미 재고에 들어간 박스의 번호 오류 | 번호 변경 불가. 취소 후 재입고만 가능 | — |

## C. 상품 결정

| 발생 | 처리 | 결과 |
|---|---|---|
| 캐시, 이전 학습, GTIN으로 상품이 하나로 정해짐 | 자동 매핑 | `NORMAL`, 재고 즉시 |
| 발주서 후보 상품이 하나 | 그 상품으로 확정 (부위·냉장/냉동은 발주서대로) | 입고 |
| 후보가 여럿 | `PENDING_MAPPING`, 후보 버튼 표시 | 고르면 입고. 후보 선택은 기억하지 않고 GTIN만 학습 |
| 발주서가 있는데 맞는 상품이 없음 | 새 상품을 만들지 않고 보관. 그 거래처의 열린 발주 상품 드롭박스 표시 | 고르면 입고 |
| 냉장/냉동을 모름 (소·돼지·닭·오리) | 보관 후 냉장/냉동 버튼 표시 | 고르면 입고 |
| 거래처를 골랐는데 열린 발주서가 없음 | 상품 자동 생성 (판매중지, 가격 0. 보관된 같은 조합이 있으면 보관만 풀어 재사용). 이어서 "발주서에 없는 물건"으로 판정 | 기본 설정(REJECT)이면 박스는 거절되어 재고 X, 거절 기록과 생성된 상품만 남음. 설정이 HOLD면 받아서 보류함. 의도된 동작(사장님 확인 2026-10-03) |
| 거래처 없이 들어온 스캔 (엑셀) | 상품 자동 생성, 발주서 판정 없음 | 입고. 노랑 안내가 뜨고, 가격을 넣어 "판매중"으로 바꿔야 고객에게 보임 |
| 한 코드에 여러 상품이 섞여 옴 | "박스 분류입고": 같은 코드로 (상품, 무게)를 행마다 입고 | 행마다 별도 박스. 한 행이 실패하면 거기서 멈추고 앞 행은 유지. 발주서에서 한 줄이라도 거절되면 전부 취소 |
| 로트(묶음번호) 안에 등급이 섞임 | 현재는 첫 개체 등급으로 표시 | **알려진 구멍**. 재설계안(`docs/stock-redesign-boxes-and-conditions.md`)은 승인 대기, 코드 없음 |

## D. 발주서 판정 (거래처를 싣고 찍은 스캔만 해당)

| 발생 | 처리 | 결과 |
|---|---|---|
| 열린 줄에 맞고 남은 자리가 있음 | `ASSIGNED`. 발주일, 작성 시각, 줄 번호 순으로 채우고 한 박스가 여러 줄에 나뉠 수 있음 | 재고 즉시. 받은 양과 남은 양 표시 |
| 이 박스로 모든 줄이 참 | 발주서 자동 마감 ("발주종결") | 같은 품목이 더 오면 초과로 처리 |
| 덜 오고 끝남 | 자동 마감 안 됨 | 사람이 "발주강제종결" |
| 초과가 허용 오차(%/kg) 안 | 마지막 줄에 얹음 | 정상 입고 |
| 초과가 허용 오차 밖 | `OVER_PENDING` "받을까요?" (현장 직원이 즉답, 승인 불필요, 마이그레이션 221) | 아래 두 행 |
| ↳ 받기 | `OVER_HELD`, 넘친 무게는 어느 줄에도 안 붙임 | 재고에 들어가 판매 가능. 사무실이 확인 |
| ↳ 거절 | `REJECTED`, 스캔 VOIDED | 재고에 없음. `inbound_rejections`에 거절 기록만 남음 |
| 결정 전에 "주문에 바로 배정"을 누름 | 출고를 건너뜀 (221에서 수정) | 되돌릴 수 없는 상태를 방지 |
| 발주서에 없는 물건 | 입고 기준 설정에 따라 REJECT 또는 HOLD | REJECT: 거절하고 기록. HOLD: `UNLISTED_HELD`, 재고에 들어가고 보류함으로 |
| 보류함에서 처리 | owner/manager가 "발주서 추가 생성" | 발주서가 사후 등록됨 |
| 상품이 아직 미정인 박스 | 판정 보류 | 상품이 정해지는 순간 같은 판정을 함 |
| 박스를 취소함 | 채움이 사라짐 | 자동 마감됐던 발주서가 다시 열림 (사람이 닫은 것은 그대로) |
| 자동 마감된 발주서의 품목이 더 옴 | 초과로 판정 | 위 "초과" 행과 동일. 사람이 닫은 발주서면 "없는 물건" 기준을 따름 |

## E. 중량과 기한

| 발생 | 처리 | 결과 |
|---|---|---|
| 표기중량과 실중량 차이가 ±2% 이내 | — | 정상. 재고와 매입금액은 실중량 기준 |
| 차이가 ±2% 초과 | 입고는 막지 않음. 노랑 경고 | 매입 정산에서 "오차 초과" 건수와 차액으로 집계 |
| 매입단가 없음 | 금액을 비워 둠 | 관리자가 매입 정산에서 채움. 직원에게는 금액이 안 보임 |
| 유통기한 지남 | 입고는 기록, 빨간 경고 | 출고는 `BOX_EXPIRED`로 차단 (확인 버튼으로 못 넘김) |
| 유통기한 D-3 이내 | 안내 | 출고 가능. 임박 알림벨에 표시 |

## F. 정정과 취소

| 발생 | 처리 | 결과 |
|---|---|---|
| 잘못 입고한 박스 | VOID. 삭제가 아니라 반대 부호 행(역분개) 추가 | 재고 복원. 일부라도 출고된 박스는 `PARTIALLY_SHIPPED`로 차단 |
| 이미 판 재고를 취소하려 함 | `stock_quantity >= 0` 제약이 막음 | 취소 불가 |
| 재고에 있는 박스가 파손·폐기됨 | 박스 폐기 (대표 전용, 일부 중량 가능) | 장부에 `LOSS` 기록과 손실 금액 |
| 재고, 박스, 원장이 어긋남 | 매일 크론이 감지. 장부 불일치 화면에서 보정 | 사유가 붙은 보정 기록이 추가됨 |

## G. 기타 경로

| 발생 | 처리 | 결과 |
|---|---|---|
| 엑셀 대량 입고 | 브라우저가 20건씩 반복 호출. 거래처를 안 실어 발주서 판정과 중복 검사를 받지 않음 | 소·돼지·닭·오리 행은 냉장/냉동을 몰라 전부 "상품 확인 필요"로 보관됨 (알려진 결과) |
| 원장 도입 전에 수동 재고가 있던 상품 | 첫 편입 때 기존 재고를 `OPENING_BALANCE`로 이관 | 재고가 증발하지 않음 |
| 이력번호가 아예 없는 박스 | **미구현** ("가입고" 설계안은 사장님이 "기다려"라고 한 상태) | 현재는 처리 경로 없음 |

## 알려진 한계

- `docs/purchase-order-receiving.md`는 초과 입고를 "설정(`over_item_policy`)으로 정한다"고 적고 있으나, 마이그레이션 221 이후 실제 동작은 위 D의 "받을까요?" 방식이다. 설정은 "발주서에 없는 물건"에만 남아 있다.
- 로트 안 등급 혼합과 엑셀의 냉장/냉동 열 부재는 미해결이다.
- 위 흐름 전체를 실계정 화면에서 눌러 확인한 기록은 없다.
