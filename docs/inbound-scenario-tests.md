## 이번에 확인·발견한 것

- 시나리오 테스트가 실제로 문제를 잡는지 **변조 검사**를 했다: 소 유니크 인덱스를 지우고 돌리면 SC-3a가 실패한다(인덱스 복원 확인).
- 동시성 스크립트는 패치 전 자동 생성 함수로 되돌리면 `PRODUCT_NOT_FOUND`로 실패하고, 패치 후 통과한다.
- **발견·수정 1 — 한국 엑셀 CSV(CP949) 글자 깨짐:** 명세서 CSV를 브라우저가 UTF-8로만 읽어, 한국 엑셀의 "CSV(쉼표로 분리)"(CP949)는 품목명이 깨졌다(깨진 부위로 이상한 상품이 자동 생성될 수 있음). `decodeDocumentFileText`가 UTF-8로 안 읽히면 EUC-KR로 다시 읽도록 고침(명세서 올리기·엑셀 대량 입고 둘 다).
- **발견·수정 2 — 한글 파일명이면 원본이 보관되지 않음:** Storage 객체 키가 ASCII만 받아 `거래명세서.pdf` 같은 이름은 InvalidKey(400)로 거부됐다. 사진·스캔본은 원본이 유일한 내용이라 치명적. 키를 `고유값.확장자`로 바꾸고 원래 이름은 `file_name`에 유지.
- **현재 설계로 남은 한계 (버그 아님, 결정 필요):** ① `.xlsx`는 읽지 않고 안내만 한다(폰 파일 선택창에도 안 뜸) — 이메일 첨부가 xlsx면 CSV 저장·복사 붙여넣기가 필요. ② 부위는 "부위" 칸이 있을 때만 읽는다 — 품목명에 섞여 오는 명세서(부위 칸 없음)는 상품이 "(부위 미지정)"으로 만들어진다. ③ 종이(실물) 명세서는 사진으로 보관만 되고 대조·자동 연결은 안 된다(글자 인식 없음).
- 발견한 버그: 동시성 스크립트가 로컬 DB의 `upsert_master_livestock` 권한을 `authenticated`에 열어 둔 채 끝나 다른 DB 테스트 3건이 실패했다 → 스크립트가 권한을 되돌리도록 수정(라이브 무관).
- 세트 번호(`SET-…`)를 입고 화면에서 거부하던 가드를 지웠다. 이제 그런 값은 형식만 맞으면 다른 이력번호처럼 조회 실패(예외) 스캔으로 기록된다(더는 발행하지 않는 번호라 의도된 결과).

## 따라가기 테스트 (2026-09-26, `tests/integration/inbound-follow-along.itest.ts` 3건)

화면이 실제로 쓰는 조회(`loadInboundData`)로 하루를 걸으며 현장 카드·사무실 카드가 단계마다 맞는 말을 하는지 본다.
- **하루 흐름**: 전표 3줄 → 한 박스 → 스캔 종료 → 더 찍음(종료 저절로 풀림) → 전표에 없는 박스 → 마지막 박스(저절로 마감, 현장 카드는 시작 상태) → 그 박스 취소(전표 저절로 다시 열림) → 재스캔(다시 마감).
- **확인 필요 박스가 최근 100건 밖으로 밀려나도** 입고 화면 목록·카드 링크(`#scan-…`)에 남는다. 전에는 종 배지는 세는데 화면에서는 사라져 찾을 수 없었다(재현 후 `inbound-data.ts`에서 확인 필요 박스를 따로 조회해 합침).
- **카드 버튼이 가리키는 자리(`INBOUND_ANCHORS`) 5곳이 화면에 id로 실제 존재**한다.
- 화면 문구 정합: "박스가 더 오면 '스캔 다시 시작'을 누르세요"는 종료가 저절로 풀리게 바뀐 뒤 사실과 달라 "그냥 찍으세요 — 저절로 다시 시작됩니다"로 고쳤다.
