# 핫딜/맞춤단가 버그 수정 4건 — 실계정 테스트 방법 (2026-09-21)

`/code-review high .`로 찾아서 고친 버그 4개를 실제 화면에서 확인하는 절차. 코드는 이미 고쳐서 커밋까지 끝났고, 실제로 잘 고쳐졌는지 눈으로 확인만 하면 됨.

다 "일부러 문제 상황을 만들어서 → 예전엔 이랬는데 → 지금은 이렇게 바뀌었는지" 확인하는 방식.

---

## 1. 핫딜을 껐다가 다시 켜면 옛날 가격이 남던 문제

**예전 문제**: 핫딜을 만들었다가 전체 끄기로 끄고, 나중에 다른 가격으로 다시 시작하면 — 꺼져 있던 고객만 예전 가격 그대로 남아있었음.

**확인 절차**
1. `맞춤단가관리` 화면 → `핫딜` 섹션으로 이동
2. 상품 하나를 골라서 "전체 고객에게 일괄 생성" — 가격은 예를 들어 **10,000원**으로 입력, 저장
3. 방금 만든 핫딜 목록에서 그 상품의 "상품 단위 일괄 끄기" 버튼으로 전부 끄기
4. 같은 상품으로 다시 "전체 고객에게 일괄 생성" — 이번엔 가격을 **12,000원**으로 입력, 저장
5. 목록에서 그 상품에 걸린 모든 고객의 가격을 확인

**기대 결과**: 모든 고객이 **12,000원**으로 표시되어야 함 (일부가 10,000원으로 남아있으면 버그가 재발한 것).

---

## 2. 거래중지한 고객에게 핫딜이 계속 보이던 문제

**예전 문제**: 어떤 고객사를 "거래중지"로 바꿔도, 그 고객이 미니샵에 들어가면 핫딜 상품과 핫딜가가 그대로 보였음.

**확인 절차**
1. 테스트로 써도 되는 거래처 하나를 골라서, 그 고객사 상품에 핫딜을 하나 걸어둠 (섹션 1 참고)
2. `고객관리` 화면에서 그 거래처를 "거래중지" 처리
3. 그 고객사의 카카오 계정으로 미니샵(`/shop/...`) 접속
4. 핫딜 탭과 일반 상품 탭을 둘 다 확인

**기대 결과**:
- 핫딜 탭에 그 상품이 더 이상 안 보여야 함
- 일반 탭에서 그 상품이 **기준 가격(정가)**으로 보여야 함 (핫딜가/핫딜 배지가 없어야 함)

(참고: 어차피 거래중지 고객은 주문 자체를 넣을 수 없게 이미 막혀 있었음. 이번 수정은 "주문은 못 하는데 화면엔 핫딜가가 계속 보이던" 표시상의 문제를 고친 것.)

테스트 끝나면 그 거래처는 다시 "거래재개"로 되돌려놓을 것.

---

## 3. 상품수정 화면을 열어둔 사이 목록에서 판매상태를 바꾸면 덮어써지던 문제

**예전 문제**: 상품수정 화면을 열어놓고 한참 있다가 저장을 누르면, 그 사이에 상품목록에서 "판매중/판매중지" 토글로 바꿔놓은 상태가 저장할 때 조용히 원래대로 되돌아갔음.

**확인 절차** (브라우저 탭 2개 필요 — PC라면 탭 2개, 아니면 PC+휴대폰 둘 다 로그인)
1. 탭 A: 상품 목록에서 아무 상품이나 "상품수정" 화면으로 들어가기
2. 탭 B: 상품 목록으로 가서 (탭 A와 같은 상품) 목록의 빠른 토글로 "판매중 ↔ 판매중지" 바꾸기
3. 탭 A로 돌아와서 (새로고침하지 말고) 가격 등 아무 값이나 살짝 고친 뒤 저장 버튼 누르기

**기대 결과**: 저장이 그냥 되면 안 되고, **"상품을 찾을 수 없거나 다른 곳에서 먼저 변경되었습니다. 새로고침 후 다시 시도해주세요."** 라는 안내가 뜨면서 저장이 막혀야 함. (예전엔 아무 경고 없이 저장되면서 탭 B에서 바꾼 판매상태가 도로 뒤집혔음.)

이 안내가 뜨면 탭 A를 새로고침해서 다시 저장하면 정상적으로 됨 — 그것도 같이 확인.

---

## 4. 꺼진 핫딜/맞춤단가를 "수정"으로 가격만 바꾸면 계속 꺼진 채로 남던 문제

**예전 문제**: 고객 하나에게 걸린 핫딜/맞춤단가를 껐다가, 그 줄의 "수정" 버튼으로 가격만 바꿔서 저장하면 — 가격은 바뀌는데 여전히 꺼진(비활성) 상태로 남아있었음. 화면엔 목록에 흐리게(꺼진 채로) 표시됨.

**확인 절차**
1. `맞춤단가관리` 화면에서 고객 1명 + 상품 1개로 핫딜 또는 맞춤단가를 하나 만듦 (예: 10,000원)
2. 그 줄의 ON/OFF 토글로 끔
3. 같은 줄의 "수정" 버튼으로 들어가서 가격을 12,000원으로 바꿔서 저장

**기대 결과**: 저장 후 그 줄이 **켜진(ON) 상태**로, 가격은 **12,000원**으로 표시되어야 함. (꺼진 채로 남아있으면 버그가 재발한 것.)

---

## 5. 이력보기 버튼 이름 변경 + 모바일에서 이력 모달 카드형으로 전환

**예전 문제**: 상품관리의 "이력보기" 버튼 이름이 너무 길었고(예: "가격·단위·재고·판매상태 이력"), 모바일 화면에서 이력 모달을 열면 표 칸이 너무 좁아져서 글자가 한 글자씩 세로로 눌려 보였음.

**확인 절차**
1. `상품관리` 화면에서 상품 하나의 이력 버튼을 확인 — 이름이 짧게 "이력보기"로 나오는지
2. 휴대폰(또는 PC 브라우저 창을 좁게 줄이거나 개발자도구 모바일 보기)으로 그 버튼을 눌러 이력 모달 열기
3. 가격/재고/판매상태를 바꾼 적 있는 상품으로 테스트 — 이력이 표가 아니라 세로로 쌓인 카드 형태로 보이는지 확인
4. 같은 이력 컴포넌트를 쓰는 `맞춤단가관리`(맞춤단가·핫딜)와 발주 상세 화면의 이력 모달도 모바일에서 같이 확인

**기대 결과**: 버튼 이름이 "이력보기"로 짧게 보이고, 모바일에서 글자가 세로로 눌리지 않고 카드 목록으로 자연스럽게 읽혀야 함.

---

## 6. 맞춤단가/핫딜 저장 시 소속 정보 확인 로직 추가 (보안 수정)

**예전 문제** (코드리뷰로 발견 — 실제 피해 사례는 없었음): 회사(조직)와 도매업체 연결 정보가 비어있는 특수한 상태에서 맞춤단가/핫딜을 저장하면, "이 상품이 내 것인지" / "이 거래처가 내 고객인지" 확인이 생략될 수 있었음. 이번에 그 확인이 항상 실행되도록 막는 코드를 추가함.

**확인 절차** (정상 흐름이 그대로 잘 되는지 확인하는 용도 — 이 수정이 막는 비정상 상태 자체는 정상 계정에서는 애초에 안 생기는 상태라 그대로 재현해서 테스트하기는 어려움)
1. `맞춤단가관리` 화면에서 평소처럼 고객 1명 + 상품 1개로 맞춤단가(또는 핫딜) 새로 저장
2. "전체 고객에게 일괄 생성"도 한 번 확인

**기대 결과**: 평소와 똑같이 정상 저장되어야 함. 혹시 저장이 안 되거나 "공급사 정보를 확인할 수 없습니다" 오류가 뜨면 — 정상 계정인데 막힌 것이므로 바로 알려줄 것.

---

## 참고

- 여섯 건 다 코드 레벨(`tsc --noEmit`, `npm run build`)로는 이미 확인 끝난 상태. 이 문서는 실계정 화면에서 눈으로 보는 확인용.
- 테스트용으로 만든 핫딜/거래중지 상태는 확인 끝나면 원래대로 정리해둘 것 (실제 고객에게 테스트 데이터가 보이지 않도록).
