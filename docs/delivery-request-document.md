# 배송의뢰서 자동 생성 (16단계, delivery-tracking 연장)

## 배경
사장님 요청: 입출고처럼 배송 쪽도 궁극적으로 자동화하고 싶다 — 포장이 끝나면 버튼 하나로
운송사에 배송 의뢰가 나가고, 운송장번호까지 자동으로 채워지면 좋겠다는 것.

이 단계에서 만든 건 그 중 **문서 생성 부분만**이다. 실제 택배사 API로 자동 발급까지 가려면
택배사별 B2B API 문서(계약해야만 받을 수 있음, 공개 스펙 없음)가 필요한데 아직 없다 — 문서
없이 추측으로 만들면 실제 문서를 받았을 때 거의 다시 짜야 할 가능성이 커서(정부 공공API와
다른 리스크) 지금은 만들지 않았다. 문서/계약이 생기면 이 위에 API 자동 호출을 얹는다.

## 잠긴 설계 결정
- **운송장 발급 대행이 아니다.** `docs/delivery-tracking.md`의 "정산/운송장 발급 대행 아님"
  원칙을 깨지 않는다 — 이 문서는 화물기사님/택배사에 전달할 의뢰 내용(품목·수량·주소)을
  정리해줄 뿐, 실제 접수는 공급사가 직접(전화·카톡·택배사 앱 등으로) 한다.
- **가격 정보를 담지 않는다.** 운송사는 가격을 알 필요가 없다 — 거래명세서와 달리 단가/합계
  없이 품목명·수량·단위만 표로 낸다.
- **중량은 kg 단위 품목만 합산해서 참고용으로 보여준다.** 마리·박스 등 다른 단위는 합산 대상이
  아니다(의미가 없음). kg 품목이 하나도 없으면 총 중량 줄 자체를 생략한다.
- **API 자동발급 자리는 비워둔다.** 지금은 문서 생성 + 다운로드/미리보기만 있고, "배송의뢰
  보내기" 같은 API 호출 버튼은 없다. 택배사 문서가 생기면 택배사별 어댑터를 하나씩 추가하고
  (설정 화면에서 택배사 선택 + API 자격정보는 알림톡·PG와 같은 공급사별 암호화 저장 패턴),
  없는 택배사는 "아직 지원하지 않습니다"로 안내하며 지금의 수동 흐름(문서 참고 → 운송장번호
  직접 입력)이 계속 동작한다.

## 아키텍처
`lib/orders/statement.ts`의 거래명세서 PDF 파이프라인과 완전히 같은 구조를 재사용한다
(폰트 등록, 응답 빌더, 필수정보 누락 시 422 안내 페이지, 카카오 인앱 "외부 브라우저에서
열기" 토큰까지 전부 동일 패턴).

- **데이터 로더**: `lib/orders/delivery-request.ts` — `order_items`를 `products(unit)`과
  조인해 품목 단위를 가져온다(order_items 자체에는 unit 컬럼이 없음). 출고 마감 후엔
  `shipped_quantity`를 우선한다(거래명세서와 동일 원칙).
- **PDF 렌더러**: `lib/pdf/delivery-request.tsx` — `transaction-statement.tsx`와 같은
  Noto Sans KR 폰트/스타일 구조, 가격 컬럼만 뺐다.
- **응답 빌더**: `lib/pdf/delivery-request-response.ts` — `statement-response.ts`와 동일 패턴.
  발송인(공급사) 사업장 주소 미등록 시 422 안내 페이지로 막는다(거래명세서와 같은 기준).
- **라우트**: `app/dashboard/orders/[id]/delivery-request/route.ts` (공급사 전용).
- **외부 열기**: `lib/pdf/external-open-token.ts`의 `ExternalOpenDocumentKind`에
  `"delivery-request"` 추가, `app/doc/[token]/route.ts`에서 분기 처리.
- **화면**: `app/dashboard/orders/[id]/page.tsx` 헤더에 `StatementPreviewButton`을 그대로
  재사용해 "배송의뢰서" 버튼 추가(거래명세서 버튼 옆).

## 남은 과제
1. **택배사별 실제 API 자동발급** — 문서/계약 확보 필요. 확보되면 공급사별 자격정보 저장
   구조(알림톡·PG 패턴)부터 추가.
2. **목록 화면 일괄 처리** — `/dashboard/orders`에서 여러 주문을 체크박스로 선택해 한 번에
   배송의뢰서를 생성/처리하는 기능. 사장님 확인: 개별 주문 화면부터 먼저 만들고 그 위에 얹기로
   함(2026-09-23). 아직 미착수.
3. **실계정 검증 안 함** — 빌드(`npm run build`)만 통과 확인.
