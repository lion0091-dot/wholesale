# 📘 AI 코딩 에이전트 개발 & B2B SaaS 재사용 플레이북 (`AI_DEV_PLAYBOOK.md`)

다른 Next.js + Supabase 프로젝트를 개발하거나 AI 코딩 에이전트(Claude Code 등)를 활용할 때 즉시 재사용할 수 있는 개발 노하우, 토큰 절감 세션 패턴 및 B2B 보안 라우팅 아키텍처 가이드입니다.

## 1. AI 코딩 에이전트 토큰 절감 & 세션 관리 (Token-Saving Workflow)

### 1.1 `git commit` ➔ `/clear` 세션 리셋 패턴 (비용 1/10 절감)
- **원인:** 코딩 에이전트는 대화가 길어질수록 과거의 모든 대화 내역과 읽어들인 소스코드를 매 질문마다 백그라운드에서 다시 통째로 보냅니다. 대화가 20~30턴을 넘어가면 질문 한 마디에 수십만 토큰이 소모됩니다.
- **해결책:**
  1. 단위 기능 구현 및 `npx next build` 검증이 통과하면 즉시 `git commit`을 실행하여 로컬 복구 지점을 만듭니다.
  2. 커밋 직후 Claude Code 터미널에서 **`/clear`**를 입력하여 누적된 컨텍스트를 비웁니다.
  3. 깨끗하고 가벼운 상태에서 다음 개발 과제를 시작합니다.

### 1.2 핀포인트 UI 수정 및 로직 변경 금지 제약
- **원인:** *"전체적으로 화면 다 예쁘게 고쳐줘"* 같은 광범위한 지시는 에이전트가 모든 컴포넌트 파일과 CSS를 다시 읽고 재작성하면서 토큰 폭탄을 유발합니다.
- **해결책:**
  1. 수정할 파일 1개만 단일 지정합니다. (예: `app/onboarding/page.tsx`)
  2. 프롬프트에 **`"기능이나 DB/서버 로직은 절대 변경하지 말고, Tailwind CSS 클래스(여백, 폰트 색상, 라운딩)만 정돈해라"`**라는 제약 조건을 명시합니다.

### 1.3 CLI 페이저 멈춤 방지
- 에이전트가 `git diff`를 실행할 때 입력 대기 상태에 빠지는 현상을 막기 위해 `git --no-pager diff --stat` 명령을 활용하거나 `q` 키를 눌러 탈출합니다.

## 2. Next.js & Supabase B2B 보안 라우팅 아키텍처

### 2.1 독립 온보딩 라우트 분리 (`/onboarding`)
- **문제점:** 대시보드 레이아웃(`app/dashboard/layout.tsx`) 내에 온보딩/가입 화면이 종속되어 있으면 미들웨어 조건에 따라 무한 리다이렉트 루프(Infinite Loop)가 발생할 수 있습니다.
- **해결 패턴:**
  - 백오피스 대시보드 레이아웃을 타지 않는 독립된 관문 라우트(`app/onboarding/page.tsx`)를 구축합니다.
  - 미들웨어(`middleware.ts`)에서 조직(Organization)이나 사업자 승인이 완료되지 않은 신규 가입 계정을 `/onboarding`으로 자동으로 포획 및 리다이렉트합니다.

### 2.2 개발 모드 우회 가드 (`Dev Org Bypass`)
- **목적:** 로컬 개발 및 기능 테스트 시 매번 조직 할당이나 사업자 승인 과정을 거치지 않고 빠르게 테스트할 수 있도록 안전장치를 마련합니다.
- **구현 패턴:**
  - `NODE_ENV=development` 조건에서만 임시 기본 조직을 할당하거나 미들웨어를 통과시키는 우회 로직을 적용합니다.
  - 프로덕션 환경(`NODE_ENV=production`) 배포 시 해당 로직이 자동으로 무력화되도록 설계합니다.

## 3. B2B 폐쇄형 UI/UX & 데이터 연결 패턴

### 3.1 단골 식당 카드 그리드(섬네일) 뷰
- **개념:** 도매업자가 식당별 VIP 차등 맞춤 단가 및 1클릭 카카오톡 초대 토큰 링크(`?retailer=`)를 한눈에 관리하는 카드형 UI 패턴입니다.
- **주요 기능:**
  - 식당별 고유 초대 링크 1클릭 클립보드 복사.
  - 식당별 맞춤 단가 설정 페이지 직통 연결.
  - 상호명, 사업자번호, VIP 뱃지 등 핵심 정보 시각적 강조.

### 3.2 1:1 폐쇄형 미니샵 토큰 진입 (Dynamic Routing)
- **개념:** 불특정 다수에게 가격이 노출되는 오픈마켓이 아닌, 초대받은 식당만 접근할 수 있는 폐쇄형 B2B 스토어입니다.
- **구현 패턴:**
  - 고유 초대 토큰/URL 기반으로 식당 계정이 진입할 때 해당 도매업자의 상품 및 해당 식당 전용 맞춤 단가만 노출되도록 Supabase RLS와 Dynamic Routing을 연결합니다.

## 4. Supabase DB 보안 및 RBAC 권한 분리

### 4.1 Row Level Security (RLS) 스페이스 격리
- 도매업자 간 멀티 테넌트 데이터를 DB 레벨에서 완전 격리하여 타 도매업자의 상품, 공급가, 거래처 정보를 절대 조회할 수 없도록 차단합니다.

### 4.2 RBAC (역할 기반 접근 제어) 엄격 분리
- 한 계정이 도매업자(Seller)와 식당(Buyer) 권한을 동시에 가질 수 없도록 차단하여 가격 탐색(스파이 행위)을 방지합니다.
