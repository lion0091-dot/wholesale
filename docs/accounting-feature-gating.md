# 회계 기능을 나중에 유료로 묶을 때 — 꺼도 되는 것과 조심할 것 (2026-10-04)

**결정(대표):** 지금은 회계 관리 메뉴와 탭을 **전부 기본 켜짐**으로 둔다. 나중에 유료 서비스를 시작할 때 일부를 꺼서 묶는다. 이 문서는 그때 "꺼도 업무가 안 막히는 것"과 "끄면 막히는 것"을 미리 갈라 둔 점검표다.

켜고 끄는 방법과 구조는 [wholesaler-features.md](wholesaler-features.md)를 본다(운영자가 `/admin/features`에서 업체별로, 함수는 `set_wholesaler_feature`). 켠 기간은 이력으로 남아 일할 계산의 근거가 된다.

**확인 방법과 한계:** 아래는 기능 키를 쓰는 DB 함수와 화면 코드를 읽어서 정리했다. 실제로 끈 상태에서 화면을 눌러 본 것은 아니다. 유료화 전에 대표 계정으로 끈 업체를 하나 만들어 아래 표의 "계속 되는 것"을 눌러 확인한다.

## 한눈에 보기

| 기능(키) | 끄기 | 한 줄 이유 |
|---|---|---|
| 손익 관리 (`accounting_pnl`) | **안전** | 조회 전용. 기록은 계속 쌓이고 켜면 과거 것이 그대로 보인다 |
| 계산서 집계 (`accounting_tax_invoices`) | **안전** | 조회 전용. 계산서 작성 도우미·발행은 주문 상세에서 따로 계속 된다 |
| 재고 조정·손실 (`accounting_stock_adjust`) | **안전** | 조회 전용. 감량·폐기·수율 손실·장부 보정은 다른 화면에서 계속 입력되고 기록이 쌓인다 |
| 원가 관리 (`cost_management`) | **안전** | 주문 마진 패널과 재고 평가가 사라질 뿐. 원가 기록은 계속된다 |
| 미수금 정산 (`accounting_receivables`) | **안전(조건부)** | 현황 화면·독촉 발송·변경 이력이 사라진다. 외상 입금 확인은 빠른 정산에서 계속 된다 |
| 장부 불일치 (`accounting_integrity`) | **주의** | 점검은 계속되지만 고치는 화면이 막힌다 |
| 매입 정산 (`accounting_purchases`) | **비권장** | 입고한 박스의 단가를 나중에 고치는 길이 막힌다 |
| 회계 관리 메뉴 (`accounting`) | **주의** | 부모다. 끄면 아래 탭이 전부 같이 꺼진다(매입 정산 포함) |

## 기능별 설명

### 안전하게 끌 수 있는 조회 전용 탭

**손익 관리**
- 끄면: 기간별 매출·매출원가·매출총이익 화면(`/dashboard/stock-pnl`)과 DB 조회 함수(`get_pnl_by_month`·`get_pnl_by_product`)가 막힌다.
- 계속 되는 것: 출고 마감, 매출 확정, 원가 기록 전부. 손익은 이 기록을 읽어 보여 줄 뿐이라 데이터가 사라지지 않는다.
- 다시 켜면: 꺼 둔 동안의 기간도 그대로 계산돼 보인다.

**계산서 집계**
- 끄면: 월별·거래처별 발행 현황과 "챙길 주문" 화면(`/dashboard/tax-invoices`)이 막힌다.
- 계속 되는 것: 계산서(면세) 작성 도우미 PDF와 발행 이력 기록은 주문 상세 쪽이라 이 기능과 무관하다.

**재고 조정·손실**
- 끄면: 손실·조정 기록 조회 화면(`/dashboard/stock-adjustments`)이 막힌다.
- 계속 되는 것: 입력은 다른 화면이다 — 상품 관리의 재고 조정, 소비기한 화면의 박스 폐기, 출고 화면의 감량, 쪼개기의 수율 손실. 모두 장부(`stock_ledger`)와 폐기 이력(`box_disposals`)에 계속 쌓인다.
- 다시 켜면: 그동안 쌓인 기록이 한꺼번에 보인다.

**원가 관리**
- 끄면: 주문 상세의 원가·마진 패널, 재고 평가 탭(`/dashboard/stock-valuation`), 팀 관리의 "원가 볼 사람" 허용 칸이 사라진다.
- 계속 되는 것: 입고 때 매입단가 입력과 박스 원가 기록, 쪼개기 원가 배분(마이그 231)은 이 기능 키와 상관없이 돌아간다.

### 조건이 붙는 것

**미수금 정산**
- 끄면: 미수금 현황 화면, 독촉(리마인드) 발송, 변경 이력 조회가 막힌다(화면과 서버 액션에서 막음).
- 계속 되는 것: 외상 입금 확인은 `settleCreditOrdersAction`이라는 기능 검사가 없는 액션이고, 빠른 정산 화면(`/dashboard/quick/settle`)에서 쓸 수 있다. 외상 한도 계산과 주문 거절 규칙도 그대로다.
- 조건: 외상 거래를 하는 업체에게는 현황을 못 보는 불편이 크다. 독촉 알림톡이 이 탭에 묶여 있어서, 알림톡을 쓰는 업체에는 가치가 큰 기능이다 — 유료화 때 "묶기 좋은 대상"이지만 꺼진 업체에는 빠른 정산 경로를 안내해 둔다.

### 주의해서 다뤄야 하는 것

**장부 불일치**
- 끄면: 어긋난 항목 목록과 보정 화면(`list_stock_mismatches`·`list_stock_repairs`·`repair_stock_mismatch`)이 막힌다.
- 계속 되는 것: 매일 도는 재고 일치 점검 크론은 이 기능과 별개라 계속 돌고, 어긋나면 운영자의 작업 상태 화면에 빨간색으로 보인다.
- 위험: 장부가 틀어져도 업체 대표가 스스로 고칠 방법이 없다. 꺼진 업체에서 어긋남이 생기면 운영팀이 그 업체만 잠깐 켜 줘야 한다. 유료로 묶을 수는 있지만 이 대응 절차를 먼저 정해 둔다.

**매입 정산 — 끄지 않는 것을 권한다**
- 끄면: 매입 목록·합계 화면과 박스 매입단가 수정(`update_inbound_purchase`), 상품별 기본 매입단가 저장 화면(같은 화면에 있다)이 막힌다.
- 계속 되는 것: 입고할 때 매입단가를 넣거나 기본 단가가 자동 적용되는 것은 계속 된다.
- 위험: **입고할 때 잘못 넣은 단가를 나중에 고칠 수 없다.** 그 단가가 원가·손익·재고 평가로 흘러가므로 틀린 숫자가 고쳐지지 않은 채 남는다. 입고·쪼개기 과정에 필요한 기능이라 유료 묶음에서는 빼는 쪽을 권한다.

**회계 관리 메뉴(부모)**
- 끄면: 사이드바 메뉴가 사라지고 자식 탭이 전부 같이 꺼진다. 자식 값이 켜져 있어도 소용없다.
- 위험: 위 매입 정산의 위험이 그대로 따라온다. 일부만 묶으려면 메뉴는 켜 두고 자식 탭을 개별로 끈다.

## 묶을 때의 순서와 주의

1. 업체별로 꺼야 하면 `/admin/features`에서 끈다. 기본값을 바꾸지 않는다.
2. **기본값(`platform_features.default_enabled`)만 바꾸면 안 된다.** "켜져 있다 ⇔ 진행 중 기간이 한 줄"이라는 이력 규칙이 깨진다(점검 함수 `feature_period_violations()`가 잡는다). 기본값을 바꿔야 하면 설정 없이 기본값을 따르던 업체의 진행 중 기간을 같은 마이그레이션에서 닫아야 한다. 2026-10-04에 이 방식을 시도했다가 대표 결정으로 취소했다(적용된 DB 없음).
3. 끄기 전에 그 업체가 지금 그 화면을 쓰고 있는지 본다. 켜진 기간 이력(`/admin/features/history`)이 근거가 된다.
4. 끈 업체에는 위 표의 "계속 되는 것"을 안내한다(특히 외상 입금 확인 경로).
5. 새 선택 기능을 만들 때처럼, 끈 업체의 기존 동작은 그대로여야 한다. 끄는 것이 입력 경로를 막는 기능은 묶음 후보에서 뺀다 — 조회 전용인지가 기준이다.

## 알려진 현재 상태

- 스테이징 DB의 시우나라는 회계 관리 메뉴와 원가 관리가 꺼진 채 남아 있고, 영성 마켓은 회계 관리 메뉴가 꺼져 있다(이전에 켜고 끄는 화면을 시험하면서 남은 것으로 보인다). 운영 DB에는 꺼진 설정이 없다(2026-10-04 조회).
