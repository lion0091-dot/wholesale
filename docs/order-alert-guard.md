# 주문 알림 지킴이 (2026-10-02, 별도 기능)

카카오 채널(알림톡)은 사업자 등록 전에는 승인이 안 되므로, 공급사 주문 알림 4종(신규 주문·주문 수정·취소 요청·여신 초과 거절)은 지금 **웹푸시가 유일한 채널**이다. 웹푸시는 "켠 기기"에만 가므로, 켜는 것을 잊거나 놓치는 경우를 줄이는 장치 3개를 추가했다. 100% 보장은 불가능하다(브라우저에서 거절·폰 꺼짐·아이폰은 홈 화면 앱 설치 필요).

| | 동작 | 위치 |
|---|---|---|
| A | 이 기기에서 알림이 꺼져 있으면 대시보드 위에 빨간 줄(`알림 켜기`). 켜면 사라짐. | `components/order-alert-guard.tsx` |
| B | 이 업체로 처음 들어오면 한 번 크게 "새 주문 알림을 켜세요"(켜기/나중에). 나중에 → A만 남음. 업체별 localStorage `order-alert-prompt-seen:<wid>`. | 같은 파일 |
| F | 화면이 열려 있을 때 새 주문(orders INSERT, Realtime)이 오면 소리·진동 + 오른쪽 아래 알림 창. 소리는 종 패널 "새 주문 소리"에서 끔(`order-alert-sound-muted`). 브라우저는 첫 클릭 전까지 소리를 막아서 그 경우 창만 뜬다. | `lib/notifications/order-alert-sound.ts`, `components/order-sound-toggle.tsx` |

- 대표·매니저에게만 보인다(`app/dashboard/layout.tsx`의 `isOwnerOrManager`). 직원은 제외.
- 웹푸시 상태 로직은 `lib/hooks/use-web-push.ts`로 뺐다(`PushToggle`과 지킴이가 공유).
- 서버에 푸시 키가 없으면 A·B는 안 보이고 F만 동작한다.

## 같이 찾아 고친 버그: Realtime이 브라우저에서 변화를 못 받음

종 배지·고객 배송 벨·입고 화면의 Realtime(마이그 187)이 **로컬 브라우저에서 실제로는 안 오고 있었다**(30초 주기 조회가 가려 왔다). 구독은 "성공"으로 나오는데 내 행의 변화가 하나도 안 왔다. 같은 계정으로 Node 클라이언트는 받았다.

- 원인(추정, 수정으로 확인): 브라우저 클라이언트는 쿠키 세션을 비동기로 읽어 소켓이 토큰 없이 먼저 붙고, postgres_changes는 구독 시점의 권한으로 RLS를 판정해 변화가 전부 걸러진다.
- 수정: 구독 직전에 `authorizeRealtime()`(`lib/supabase/realtime-auth.ts`, `getSession` → `realtime.setAuth`)을 부른다. `useRealtimeRefresh`와 지킴이가 사용. 수정 후 로컬 브라우저에서 주문 INSERT 직후 배지 숫자와 알림 창이 즉시 갱신되는 것을 확인.
- 운영(호스팅 Supabase)에서도 같은 증상이 있었는지는 확인하지 못했다. 배포 후 실제 화면에서 확인할 것.

## 미검증

- 실기기 웹푸시 수신(설정은 완료, 기기에서 안 받아 봄), 소리가 실제로 나는지(자동화 브라우저는 소리 확인 불가).
- 아이폰 홈 화면 앱 안내 문구 화면.
